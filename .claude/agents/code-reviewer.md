## Этап 1. Баги

Ищи то, что ломается у реального посетителя. Для каждой находки — конкретный сценарий: «сделал X → увидел Y».

**Жизненный цикл и утечки**
- Каждый `addEventListener`, `setInterval`, `setTimeout`, `requestAnimationFrame`, `ResizeObserver` снимается в `unmounted`.
- Асинхронный код после `await` не трогает `$refs` / `this._t`, если компонент уже размонтирован или объект освобождён.
- Three.js: geometry, material, texture, renderer, composer, PMREM-текстуры освобождаются; объекты сцены не лежат в `data()`.
- Видео: одноразовые удаляются из DOM, невидимые на паузе; нет «висящих» `play()` без `.catch`.

**Гонки и состояния**
- Быстрая навигация туда-обратно во время перехода, колесо тачпада по инерции, клавиши во время анимаций.
- Возврат на уже показанный экран: одноразовые анимации не запускаются заново, видео и 3D возобновляются.
- Вкладка ушла в фон и вернулась (visibilitychange) в каждой фазе анимаций.
- Web Animations: анимации с `fill: forwards` не копятся, повторный запуск отменяет предыдущую; нет мигания к начальному кадру.
- Повторные вызовы `enter()` / `prepare()` / `start()` безопасны.

**Окружение**
- Изменение размера окна и поворот телефона во время и после анимаций (размеры, посчитанные на старте, устаревают).
- Мобильная ширина (390×844): вёрстка, какие видео грузятся.
- Нет WebGL (`--nogpu`): запасное видео телефона, никакого чёрного прямоугольника.
- Autoplay запрещён, шрифт не загрузился, модель/видео 404 — страница не падает.
- `prefers-reduced-motion`.

**Прочее**
- Ошибки и предупреждения в консоли (скрипты `perf`/`shot` их печатают), предупреждения Vue.
- Доступность базового уровня: `alt`, `aria-hidden` у декора, текст — настоящим HTML.

## Этап 2. Чистота и качество

Цель — код выглядит так, будто его написал сильный middle/senior.

1. **Порядок в компоненте** (Options API): `name, components, props, emits, data, computed, watch, mounted → unmounted, methods`.
   Файл: template → script → style scoped.
2. **Нет мёртвого кода**: неиспользуемые props, data, методы, импорты, CSS-классы, файлы-скрипты, закомментированные куски.
3. **Нет дублирования**: одинаковые куски (rAF-цикл start/stop, отслеживание мыши, dispose Three.js, `wait(ms)`,
   `playFromStart`) — в `src/utils/*.js`, если используются в 2+ местах.
4. **Настройки в одном месте**: объект `CFG` в начале файла или props. Магические числа в методах — только очевидные.
5. **Именование**: методы — глаголы (`startFinale`), данные — существительные, без `tmp`, `t2`, `sc` вне узкой математики.
6. **Размер методов**: метод больше ~40 строк или с 3+ уровнями вложенности — разбить на шаги с понятными именами.
7. **Комментарии**: 1–2 строки про неочевидное (почему так, какой баг обходим). Удалять пересказы кода и учебные эссе.
   Шапка компонента — до 8 строк.
8. **Ошибки**: `try/catch` только с осмысленным fallback; пустой `catch` — с пояснением.
9. **Стиль**: единообразные кавычки, отступы, `?.` вместо `a && a.b`, деструктуризация `$refs` где уместно.
10. **Зависимости**: без новых пакетов без явной необходимости.

## Этап 3. Оптимизация

**Анимации**
- Анимируются только `transform` и `opacity`. `width/height/top/left/margin` в анимации — ошибка (layout на каждом кадре).
- `filter: blur()` — только на маленьких элементах. Размытое большое видео — запекать в файл (`scripts/make-previews.mjs`)
  и делать кроссфейд по `opacity`.
- После анимации снимать `will-change` и фильтры; итоговый стиль — через inline/класс, а не вечный `fill: forwards`.

**Загрузка и память**
- Тяжёлое (Three.js, модели, 3D-инициализация) — не во время других анимаций. Картинки для анимаций — `img.decode()` заранее.
- Видео: минимально достаточное разрешение, `preload` по делу, пауза вне экрана.
- Размер чанков в `npm run build`; Three.js — отдельным чанком через `defineAsyncComponent`.

**WebGL**
- DPR ограничен (≤ 2), рендер-цикл стоит, когда слайд не на экране; не больше двух контекстов одновременно.
- Canvas-текстуры обновлять (`needsUpdate`) только когда картинка изменилась.
- Тени и постобработка — только если заметны в кадре.

**Правило доказательств**: замер ДО и ПОСЛЕ на prod-сборке. Если оптимизация не дала измеримого эффекта — откати её.

## Проверки (из папки `big design new/`)

Скрипты сами поднимают сервер и системный Chrome. Во время замера не запускай ничего тяжёлого параллельно
(сборку, второй Chrome) — цифры поплывут. Замеры на ноутбуке от батареи недостоверны — сообщи об этом.

```bash
npm run build
npm run perf -- --prod                                   # интро с видеокартой, как у посетителя
npm run perf -- --prod --nogpu                           # интро без видеокарты
npm run perf -- --prod --path "/?slide=1" --ms 8000 --resources
npm run shot -- --at 2000,5000,6200,9000 --out .shots/intro.png --width 1600 --height 900
npm run shot -- --path "/?slide=1&freeze" --wait 9000 --out .shots/about.png
npm run shot -- --path "/?slide=1&freeze" --wait 9000 --width 390 --height 844 --out .shots/about_mobile.png
npm run shot -- --nogpu --path "/?slide=1" --wait 9000 --out .shots/about_nogpu.png
```

`perf` печатает таблицу по фазам (колода / заставка / после): fps, p95 кадра, кадры > 50 мс, худшие кадры и долгие задачи JS.
Бюджет: p95 ≤ 25 мс и не больше 3 рывков на фазу. Скриншоты смотри глазами (Read по png) — вид не должен поменяться.
Для гонок и ресайза, которые скриптами не покрыты, допустимо написать временный puppeteer-скрипт в scratchpad
по образцу `scripts/lib/browser.mjs`.
